# Как выложить EyeTime 3.9.2 в Chrome Web Store: шаги по порядку

Контакты для формы стора и сайта: **maxbzd1600@gmail.com**, Telegram **@maxbzd**.
Всё, что нужно вставить в формы, уже лежит в репозитории; ниже написано, откуда что брать. Названия кнопок в консоли стора Google иногда меняет, смысл остаётся.

## Шаг 0. Подготовка (один раз)

1. **Аккаунт Google** с включённой двухфакторной защитой (стор требует её для разработчиков). Лучше отдельный аккаунт под проект, а не личный: письма стора и права на расширение привязаны к нему.
2. **Регистрация разработчика:** https://chromewebstore.google.com/developer/dashboard → принять соглашение → разовый взнос **5 USD** (картой). Цену на момент оплаты проверьте на странице.
3. **Раздел Account в консоли:**
   - *Contact email*: `maxbzd1600@gmail.com`, нажать *Verify* и подтвердить письмом. Без подтверждённой почты опубликовать нельзя.
   - *Trader status* (требование ЕС): если расширение бесплатное и вы не занимаетесь им как бизнесом, выберите **Non-trader**. Тогда адрес и телефон публично не показываются. Если выберете *Trader*, стор покажет ваши адрес и телефон в листинге.

## Шаг 1. Залить код на GitHub и дождаться релиза

1. Всё уже в ветке `main` (я запушил). Workflow **Release** по изменению `manifest.json` сам создаёт релиз **v3.9.2** с файлами `eyetime-chrome.zip` и `eyetime-firefox.zip`.
2. Откройте https://github.com/maxbzd/eyetime/releases и скачайте **`eyetime-chrome.zip`**. Это ровно тот файл, который тестировался в CI. Собрать самому: `npm ci && npm run build`, файл появится в `dist/`. Сборка воспроизводимая: у двух сборок одного коммита хэш одинаковый (`node scripts-dev/verify-build.mjs` это проверяет), а подлинность релизного файла проверяется командой `gh attestation verify eyetime-chrome.zip --repo maxbzd/eyetime`.
3. Если релиза нет: Actions → *Release* → *Run workflow*.

## Шаг 2. Включить страницу проекта (нужна ссылка на политику конфиденциальности)

1. https://github.com/maxbzd/eyetime → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Подождите минуту-две и откройте https://maxbzd.github.io/eyetime/privacy.html. Страница должна открыться, внизу будут ваши контакты. Без неё стор не примет форму Privacy.

## Шаг 3. Создать элемент в консоли

1. Консоль → **Add new item** → загрузите `eyetime-chrome.zip`. Консоль сама проверит манифест. Если вы увидели ошибку про длину описания или иконки, значит заливали не тот файл.
2. Зафиксируется **ID расширения**. Он нужен позже (шаг 7).

## Шаг 5. Вкладка Privacy practices

Здесь стор чаще всего задаёт вопросы, поэтому заполняйте внимательно. Все тексты в `store/LISTING.md`.

1. **Single purpose description:** раздел *Single purpose* из `store/LISTING.md`.
2. **Permission justification:** для каждого разрешения, которое консоль перечислит (`storage`, `tabs`, `webNavigation`, `idle`, `alarms`, `notifications`, `contextMenus`, `offscreen`, `favicon`, `scripting`, `declarativeNetRequestWithHostAccess`), вставьте строку из таблицы в `store/LISTING.md`. Для необязательного доступа к сайтам (*optional host permissions*) вставьте оттуда же текст про док, погоду и подключённые сервисы.
3. **Are you using remote code?** → **No**. Пояснение про `'wasm-unsafe-eval'` лежит в `store/LISTING.md` («Remote code: none…»); если консоль спросит, вставьте его.
4. **Data usage** (что собирается): пока `USAGE_ENDPOINT` в `src/shared/usage-config.js` пуст (так и есть), отметьте, что **данные не собираются**. Поставьте **три галочки** о том, что данные не продаются, не используются не по назначению и не используются для кредитных решений.
5. **Privacy policy URL:** `https://maxbzd.github.io/eyetime/privacy.html`.
6. Сохраните. Если вкладка показывает красные пункты, значит какое-то поле пустое.

## Шаг 6. Вкладка Distribution и отправка

1. **Visibility.** Рекомендую сначала выбрать **Unlisted** («только у кого есть ссылка») или **Private → Trusted testers** (добавьте свою почту и друзей). Правки после публичного релиза идут тем же ревью, а так вы за несколько дней поймаете проблемы на живых людях.
2. **Regions:** All regions. **Pricing:** Free.
3. Нажмите **Submit for review**. В диалоге выберите **Defer publishing** («опубликовать вручную после одобрения»): тогда расширение не выйдет само сразу после проверки.
4. **Ждать:** от нескольких часов до нескольких дней. Первое ревью с `tabs` и `webNavigation` может занять дольше. Ответы на типичные вопросы уже написаны в justification.

## Шаг 7. Что делать на ревью и после него

- **Если стор прислал вопрос** (письмо на `maxbzd1600@gmail.com`): отвечайте в консоли, ссылаясь на строку justification. Не меняйте пакет без необходимости, чтобы не начинать ревью заново.
- **Одобрили:** в консоли нажмите **Publish**. Если выбирали Unlisted, через несколько дней смените видимость на **Public** (*Distribution → Visibility*).
- **Ссылки на стор:** когда расширение появится, пропишите ссылку в `site/index.html` (две кнопки скачивания) и в `README.md`.
- **Ваше приложение для Windows** (`desktop/`) ставит собственное расширение с фиксированным ID, отдельное от стора. Оно с версией из стора не связано, ничего менять не нужно.

## Шаг 8. Перед нажатием «Submit»: ручная проверка на 15 минут

Эти вещи я не мог проверить без настоящих сервисов, поэтому пройдите их вручную в обычном Chrome:

1. **Установка с нуля.** `chrome://extensions` → режим разработчика → *Load unpacked* → папка `dist/chrome` (после `npm run build`). Пройдите приветствие, запустите фокус-сессию.
2. **Мгновенная блокировка.** Настройки → Блокировка → «Мгновенная блокировка» → дайте доступ к сайтам. Откройте youtube.com и reddit.com: сразу должна появиться страница паузы, без вспышки самого сайта. Нажмите «Продолжить»: сайт откроется и не вернёт вас на паузу.
3. **Шифрование синхронизации.** Нужно два браузера (или два профиля) с одним аккаунтом Google: включите синхронизацию настроек и задач, задайте парольную фразу в первом, откройте настройки во втором и введите фразу. Данные должны подтянуться.
4. **Закрыть и открыть Chrome:** синхронизация должна показать «Заблокировано: введите парольную фразу» и ничего не потерять.
5. **Консоль ошибок:** `chrome://extensions` → EyeTime → *Errors* должно быть пусто.

## Шаг 9. Следующие релизы

1. Поднять `version` в `manifest.json` (и `package.json`), добавить раздел в `CHANGELOG.md`, влить в `main`.
2. Workflow *Release* соберёт zip. Заливайте его в консоль → *Package → Upload new package* → *Submit for review*.
3. Перед каждым релизом запускайте `npm run check`: он проверит описание, скриншоты, иконки и разрешения по правилам стора.

## Если что-то пошло не так

| Ошибка в консоли | Что делать |
|---|---|
| «Description exceeds 132 characters» | Не должно быть: `npm run check` это проверяет. Убедитесь, что залит `eyetime-chrome.zip` версии 3.9.2 |
| «Screenshots must be 1280×800 or 640×400» | Берите только файлы из `store/screenshots/<язык>/` (5 штук) |
| Отказ из-за разрешений | Ответьте по justification из `store/LISTING.md`; при необходимости напишите, что `declarativeNetRequestWithHostAccess` и доступ к сайтам необязательные и спрашиваются по клику |
| «Broad host permissions» | Доступ к сайтам объявлен как **optional** и не запрашивается при установке |

Если застрянете на каком-то шаге, напишите мне, пришлите текст ошибки из консоли.
